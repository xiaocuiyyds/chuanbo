# 飞书云文档导出当前会话设计

## 目标

为「船舶操作知识问答」增加一个用户主动触发的导出功能：点击当前会话的「导出到飞书」后，在该用户自己的飞书云空间中创建一篇新的 Docx 文档，写入该会话的完整问答与参考来源，并返回可打开的文档链接。

## 范围

- 仅导出当前选中的会话；不做自动同步、批量导出或覆盖更新。
- 前端只在用户点击后请求导出，并显示进行中、成功链接或可理解的失败提示。
- 后端从既有 `data/conversations/<conversation_id>.json` 读取消息；不改变现有保存、加载和删除逻辑。
- 导出结果包含会话标题、导出时间、每轮「用户问题」和「助手回答」、以及存在时的参考来源（文件名、页码、相关度和片段）。
- 不在浏览器代码或响应体中暴露 App Secret、tenant token、user token 或 refresh token。

## 不在本次范围内

- 将后续消息追加到既有飞书文档。
- 选择目标文件夹、分享给其他成员、导出图片、同步到多维表格。
- 飞书移动端的兼容性优化；导出按钮可见，但当前以桌面端网页应用调试为目标。

## 兼容性约束

- 现有 `/api/chat` 流式协议、会话 JSON 格式、知识库上传与清空接口均不得修改。
- 飞书凭证缺失、飞书网络异常或用户未在飞书客户端中打开时，只影响导出操作；聊天、会话切换、删除和知识库功能必须继续可用。
- 新增前端状态仅属于导出按钮，不得复用或覆盖现有 `isStreaming`、问答消息、参考来源展开状态和错误状态。
- 新增后端模块不在应用启动时向飞书发起请求；仅在用户主动请求导出时读取环境变量并访问飞书 API。
- 自动化测试必须覆盖既有聊天路由的回归可用性，以及导出失败不改变本地会话内容。

## 认证与权限

采用**用户身份**而非应用身份：前端在飞书客户端网页容器中调用 `tt.requestAuthCode()` 获取一次性授权码；后端用 `FEISHU_APP_ID` 与 `FEISHU_APP_SECRET` 将授权码换成 `user_access_token`，随后以该用户身份创建和写入文档。

选择用户身份的原因是：新文档会出现在发起导出的用户自己的云空间中，用户天然可访问、编辑和管理它；避免以 `tenant_access_token` 创建后还必须额外给用户授予文档协作者权限的流程。

开发者后台需为当前应用开通「创建及编辑新版文档」（`docx:document`）权限，创建版本并发布。网页应用还需完成飞书 H5 免登/授权相关配置；前端仅在飞书环境中请求授权码，非飞书浏览器会明确提示“请在飞书客户端内打开应用后导出”。

`.env` 新增但不提交：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
```

## 数据流

```text
用户点击“导出到飞书”
  → 前端调用 tt.requestAuthCode()
  → POST /api/conversations/{id}/feishu-doc { authorization_code }
  → 后端读取本地会话并校验消息存在
  → 后端换取 user_access_token
  → 后端创建 Docx 文档
  → 后端将格式化后的会话作为文档块写入
  → 后端返回 { document_id, url }
  → 前端显示“已导出”并提供“打开飞书文档”链接
```

## 后端边界

新增专职 `rag/feishu_docs.py`：

- `exchange_user_access_token(authorization_code)`：向飞书认证接口请求短期用户令牌；配置缺失、HTTP 失败和飞书业务错误统一转换为领域异常。
- `build_conversation_blocks(messages, exported_at)`：将会话数据转换为标题、正文、来源的飞书块请求；空会话不生成文档。
- `export_conversation(conversation)`：创建文档、写入块并返回文档 ID 与 URL。

`server/main.py` 仅承担 FastAPI 路由职责：加载会话、验证请求体、调用导出服务、将可预期异常转换为 HTTP 400/502。请求不能包含 App Secret 或任意飞书 token。

## 前端边界

`frontend/src/api.js` 新增 `exportConversationToFeishu(conversationId, authorizationCode)`；只调用后端 API。

`frontend/src/components/ChatView.vue` 新增导出按钮和状态：

- 不存在当前会话、会话尚无消息或回答正在流式生成时禁用按钮。
- 点击后请求授权码；无飞书 JS SDK、授权取消或请求失败时显示错误消息。
- 后端成功后显示可点击的飞书文档链接；不自动打开新页面，避免浏览器拦截和意外跳转。

## 文档格式

文档标题：`船舶操作知识问答 - <会话标题> - <YYYY-MM-DD HH:mm>`。

正文结构：

1. 一级标题「船舶操作知识问答」。
2. 导出时间。
3. 每一轮依次包含二级标题「问题」或「回答」与正文。
4. 对每条带 `sources` 的回答附加「参考来源」小节，列出来源文件、页码、相关度和片段文本。

用户输入及模型输出均视为普通文本写入，不能作为 HTML 或飞书块结构直接透传，避免意外格式化或注入。

## 错误处理

| 情况 | 用户可见提示 | HTTP |
| --- | --- | --- |
| 没有当前会话或会话为空 | 当前会话暂无可导出的内容 | 400 |
| 不在飞书客户端 / 无 JS SDK | 请在飞书客户端内打开应用后导出 | 前端本地提示 |
| 用户取消或授权码不可用 | 未完成飞书授权，请重试 | 前端本地提示或 400 |
| 缺少服务器配置 | 尚未配置飞书应用凭证，请联系管理员 | 500 |
| 飞书认证或文档 API 失败 | 飞书文档创建失败，请稍后重试 | 502 |

后端日志可记录飞书响应中的状态码和 request ID（若有），但绝不记录 App Secret 或 access token。

## 测试策略

- 单元测试 `build_conversation_blocks`：验证标题、问答顺序、来源文本、空来源和纯文本转义。
- 单元测试 `export_conversation`：mock 飞书 HTTP 调用，验证先换 token、再创建文档、再创建块，以及返回的 URL。
- 路由测试：会话不存在/为空、缺少授权码、导出成功和飞书异常的 HTTP 响应。
- 前端构建验证：`npm run build`。
- 人工联调：在飞书桌面客户端运行本地网页应用，点击导出并确认新 Docx 归属当前用户且内容与当前会话一致。

## 验收标准

1. 用户在飞书客户端内可对有消息的当前会话点击「导出到飞书」。
2. 飞书云空间出现一篇新 Docx，且打开链接可访问。
3. 文档含完整问答和已有参考来源，不含访问凭证。
4. 非飞书环境、空会话、配置缺失和飞书 API 失败均有明确提示，且不影响原有聊天功能。
