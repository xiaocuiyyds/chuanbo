# 船舶操作知识智能问答系统 PPT 设计规格

## 目标与受众

- 用途：项目汇报。
- 篇幅：约 5 页，16:9。
- 内容重心：技术实现，以系统架构为叙事主线。
- 成功标准：听众能在短时间内理解系统如何把船舶设备手册转化为可检索、可问答、可溯源的知识库。

## 视觉方向

- 风格：“工程白板”。
- 配色：白底，深蓝为主色，青色用于强调关键模型与数据，浅灰用于网格、边界和辅助文字。
- 排版：封面简洁；内页使用大标题、左右结构和两张简洁技术链路图，避免密集卡片化。
- 图片：优先使用项目内真实手册页面截图；不使用与项目无关的装饰照片。

## 逐页内容

### 第 1 页：封面

- 标题：船舶操作知识智能问答系统
- 副标题：面向设备手册的多模态解析与 RAG 技术实现
- 视觉：左侧标题，右侧用简化技术流程线和浅网格表达“手册到答案”。

### 第 2 页：项目背景与技术目标

- 问题：手册页数多，表格与示意图密集，人工检索慢，答案缺少页码级溯源。
- 当前数据：2 份手册，共 283 页，当前索引包含 504 个知识片段。
- 技术目标：保留文档结构、实现语义检索、降低幻觉、支持多轮追问、输出来源与页码。
- 视觉：左侧放项目内真实手册页面，右侧以数字和短句说明范围与挑战。

### 第 3 页：知识库构建链路

- 链路：PDF 页面渲染 → Qwen-VL 转录 Markdown → 结构感知切分 → DashScope `text-embedding-v3` 向量化 → FAISS 持久化索引。
- 关键参数：页面约 180 DPI；切分软目标 800 字符；硬上限 1600 字符；字符回退切分重叠 100；表格拆分时重复表头。
- 工程价值：保留 Markdown 标题和表格边界，并将来源文件与页码绑定到每个片段。
- 视觉：水平五步流程，下方用参数标注表现关键细节。

### 第 4 页：RAG 问答技术架构

- 输入：用户新问题与最近 3 轮对话。
- 查询处理：DeepSeek 将带代词或省略的追问改写为独立问题。
- 检索：DashScope 生成查询向量，FAISS 使用归一化内积返回 Top 5 片段。
- 生成：将片段、文件名和页码组成上下文，DeepSeek 按“仅根据手册”的系统约束流式回答。
- 输出：答案、参考文档、页码、相似度和原文片段。
- 视觉：一张简化数据流图，将“追问理解”、“语义检索”和“可溯源生成”分成三个阶段。

### 第 5 页：实现成果与后续优化

- 已实现：多 PDF 入库、表格/图示转录、向量检索、多轮问答、流式输出、页码溯源、索引和历史持久化。
- 实例：使用 AutoChief 600 指示面板按钮功能问答，展示答案可回溯至具体手册页。
- 后续优化：建立专业问答评测集；加入 BM25 + 向量的混合检索；引入重排序；增加离线模式与权限管理。
- 视觉：左侧为真实问答摘要，右侧为已实现与下一步路线。

## 内容依据

- 项目源码：`app.py` 与 `rag/` 目录。
- 当前数据：`data/chunks.pkl` 与 `data/chat_history.json`。
- 文档范围：`KC-700 Manual.pdf` 共 171 页，`KONGSBERG AC600_MEB_FPP +(翻译结果).pdf` 共 112 页。

## 验收要求

- 输出可编辑 `.pptx`。
- 每页标题、正文、标注字号符合演示文稿可读性要求。
- 不得存在文本溢出、意外重叠、标题换行、裁切异常或未替换占位符。
- 渲染后逐页检查，并运行溢出测试。
